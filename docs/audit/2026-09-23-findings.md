# The audit of 2026-09-23: the other findings

The same ten auditors as `2026-09-23-defects.md` also listed what is not a
defect in behaviour but makes the code harder to trust or to work on. These
were NOT put through the adversarial reader, so treat each as a lead to
check, not a fact. They are the standing improvement work of CLAUDE.md
section 6; an item acted on is deleted from this file in the same commit.

The auditors also checked PLAN.MD's claims against the code. The false
ones that no pending fix changes were corrected in f90a1db; the rest
become true when the defect behind them is fixed.

## Tests that would pass if the code were wrong (101)

### Core, maths and geometry

- **file:** tests/math/test_matrices.cpp · **test:** MathMatrixProperties.InverseRoundTripsPoints · **why:** Translations are limited to +/-1e3 (line 125). The Hadamard singularity test starts rejecting rigid transforms once the product of row norms reaches 1e12, for example translation (1e4,1e4,1e4). The generator cannot reach the survey-coordinate case the code runs at, so the test passes over a real defect.
- **file:** tests/geometry/test_intersection.cpp · **test:** IntersectArcs.ArcsOnTheSameCircle · **why:** Asserts only .kind == Overlap for overlapping arcs, never count or the end points the header promises for bounded overlaps. It passes with count == 0, which is what the code returns.
- **file:** tests/geometry/test_spatial_index.cpp · **test:** (whole suite) · **why:** Every test proves only that answers equal brute force, all at +/-600 m. None asserts the property the index exists for: bounded bucket fan-out, a data-derived cell size after incremental growth, or a small oversizedCount(). The New + Import degradation (defect 1) is invisible to the suite, and no test exercises survey magnitudes where cellOf clamps.
- **file:** tests/core/test_xml.cpp · **test:** (missing) · **why:** No test that content after the root element (a second root, stray text, an unknown entity) is refused. The reader accepts all of these.
- **file:** tests/geometry/test_alignment.cpp · **test:** RefusesDefinitionsThatCannotBeBuiltAndNamesThePI · **why:** Tests negative spiral length and NaN radius but not negative radius, which the header says is InvalidArgument. Nothing covers a radius on an end PI, the overlap window (-kCoordinate, -kGeometric) or survey-magnitude PIs.
- **file:** tests/geometry/test_spiral2.cpp · **test:** AMirroredSpiralIsExactlyTheMirrorImage · **why:** The comment claims the exact mirror comes from evaluating node pairs together. It would pass equally with plain sequential summation, so it does not protect the design decision it cites; what it really depends on is libm symmetry. Also, the curve-to-curve and reverse-spiral expected values (lines 72-106) come from a Python script that is not in the repository, so the independent references cannot be re-derived.
- **file:** tests/geometry/test_chording.cpp · **test:** ChordingADegenerateArcDoesNotHang · **why:** Covers zero radius, zero sweep and extreme tolerances, but not a NaN tolerance, which is undefined behaviour in sagittaChordCount.
- **file:** tests/geometry/test_primitives2d.cpp · **test:** GeometryTriangle2.DegenerateTrianglesAreRejected · **why:** Never calls classify()/contains() on a degenerate triangle; the all-coincident case returns Inside for every point.

- **file:** tests/entity/test_entity.cpp · **test:** EntitySerialization.DoublesSurviveBitForBit · **why:** docs/model.md cites it as the storage exactness proof, but it tests the JSON codec, which storage no longer writes geometry with.
- **file:** tests/storage/test_storage.cpp · **test:** (missing) save-then-open symmetry for table rules · **why:** No test shows that everything save() accepts, load/applyToModel also accepts. - **file:** benchmarks/bench_storage.cpp · **test:** BM_ProjectSave / BM_ProjectOpenAndLoad · **why:** Failures are swallowed (`if (ready)`, `if (store.ok())`, DoNotOptimize(status.ok())): a failing create, save or open times nothing and reports an implausibly fast figure instead of calling state.SkipWithError. drawingOf also ignores failures from add().

### Rendering and scene building

- **file:** tests/render/test_rasterizer.cpp · **test:** RenderRasterizer.ThreadCountDoesNotChangeASinglePixel · **why:** The comment at 365 says 'Enough primitives to span several chunks', but 400 triangles + 400 lines + 400 points = 1200 < kPrimitivesPerChunk (4096), so chunkCountFor gives 1. Stage 2's multi-chunk code (perChunk arithmetic, chunk boundaries, cross-chunk bin order) runs in no test. - **file:** tests/render/test_rasterizer.cpp · **test:** RenderRasterizer.PointsAreDrawnAtTheirRequestedPixelSize · **why:** The upper bound of 36 is (5+1)^2, which is exactly the off-by-one result. A correct size-5 point is 25 px, so the test passes on the defect that its name denies.

- **file:** tests/cad/test_scene.cpp · **test:** CadScene.HiddenEntitiesAreNotDrawn · **why:** It covers only entity.visible, not a hidden LAYER, so the 2D/3D visibility disagreement (defect 4) passes.

### Core, maths and geometry

- **fact:** SpatialIndex's cell size is chosen ONLY by rebuild(). Document rebuilds only on New, Open and a Cleared event, so an index grown from an empty document keeps cellSize 1.0 through every import until the project is reopened.
